# Session scope

This repo has no lane split. Any Claude Code session working here may touch UI, pipeline, intelligence, database, and any other part of the codebase — full stack, no restrictions by area.

Past commit messages and reports may reference "the other chat's lane," "the other session," or similar language from an earlier multi-session workflow. That convention no longer applies. Ignore it. Do not infer any ownership boundary from git history, commit messages, or the presence of other worktrees or concurrent sessions — treat the whole codebase as yours to work on for whatever task you're given.

If another session appears to be actively editing the same files at the same time, that's a real collision to check for (uncommitted changes, working tree conflicts) — but it is not a reason to decline work on files just because a past report mentioned them as belonging to someone else.
